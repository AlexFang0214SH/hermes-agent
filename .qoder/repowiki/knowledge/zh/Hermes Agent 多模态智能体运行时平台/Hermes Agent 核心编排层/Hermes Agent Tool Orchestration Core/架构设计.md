- **Centralized Registry Pattern**: `tools/registry.py` acts as the single source of truth, where all tool modules self-register schemas, handlers, and availability checks (`check_fn`) at import time, decoupling definition from consumption.
- **Dynamic Schema Assembly**: `model_tools.py` orchestrates the filtering of tools based on session-scoped `enabled_toolsets`, applying runtime dynamic overrides (e.g., for `execute_code` or `discord` intents) and sanitizing schemas for backend compatibility before exposing them to the LLM.
- **Progressive Disclosure Bridge**: Implements a "Tool Search" mechanism (`tools/tool_search.py`) that automatically replaces large sets of deferrable (MCP/plugin) tools with lightweight bridge tools (`tool_search`, `tool_describe`, `tool_call`) when schema token usage exceeds a context-aware threshold, preserving core tool visibility.
- **Secure Execution Sandbox**: Enforces security boundaries in `tools/environments/local.py` by stripping Hermes-managed provider credentials from subprocess environments, while allowing controlled passthrough of specific variables via `tools/env_passthrough.py` (backed by skill declarations and user config) to balance capability with secret protection.
